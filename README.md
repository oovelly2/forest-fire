# 경기도 산불 위험 예측 · 사전 자원 배치 추천

산불 대응 담당자가 과거 이력을 분석하고, 지역별 *다음 날* 산불 위험을 예측해 진화 차량·인력의 사전 배치 우선지역을 판단하도록 돕는 Streamlit 서비스입니다. (산불 발생 후 투입 추천은 이번 범위에서 제외)

## 실행 방법
```bash
cd ~/work/forest-fire
pip install -r requirements.txt     # holidays(한국 공휴일) 포함. 이미 설치돼 있으면 생략
python test_core.py                 # 핵심 로직 검증 (pytest가 있으면 python -m pytest -q)
streamlit run app.py                # 화면 실행
```

## 구현 순서와 파일 역할 (core.py → 테스트 → 화면)
| 순서 | 파일 | 역할 |
|---|---|---|
| 1 | `core.py` | 읽기·전처리·지역x날짜 표·특성·모델·배치 규칙 (streamlit 사용 안 함) |
| 2 | `test_core.py` | 35개 테스트: 데이터 건수, 관측소 연결, 미래 정보 차단, 공휴일·요일 계산, 원인 표, 시간 분할, 모델 비교 조건, 배치 합계 ≤ 가용 수량 |
| 3 | `common.py`, `app.py`, `pages/1~4` | 화면. `common.get_bundle()`이 core의 `load_all()`을 한 번만 실행해 재사용 |

`core.load_all()` 데이터 흐름: `load_*` → `clean_*` → `assign_stations` → `build_panel` → `add_features` → `fit_and_evaluate` → (화면) `predict_risk` → `allocate_resources`

## 기상청 API 연동 (선택)
인증키가 있으면 위험도 확인·사전 배치 화면에서 **"기상청 API로 오늘 기준 기상 불러오기"**를 쓸 수 있습니다. 키가 없으면 이 선택지는 나타나지 않고 기존처럼 2024~2025년 자료로 동작합니다.
1. [공공데이터포털](https://www.data.go.kr)에서 *기상청_지상(종관, ASOS) 일자료 조회서비스* 활용 신청 후 인증키(일반 인증키, Decoding)를 받습니다.
2. `.streamlit/secrets.toml.example`을 `.streamlit/secrets.toml`로 복사하고 `KMA_SERVICE_KEY`에 키를 넣습니다. (이 파일은 `.gitignore`에 있어 깃허브에 올라가지 않습니다.)
3. 앱을 다시 실행합니다.

- **일자료(관측)를 쓰는 이유**: 모델이 '전날까지의 관측'으로 학습돼서, 같은 종류인 ASOS 일자료로 같은 방식의 입력을 만듭니다. 기상 *예보*는 성격이 달라 쓰지 않았습니다.
- 오늘 기준 요청은 '어제까지' 자료를 가져오며, 어제 자료가 아직 없으면(보통 다음 날 오전에 게시) 안내 문구가 나옵니다.
- 한계: 최근 90일 산불 건수는 보유 이력(~2025-12-31)만 반영하고, 모델은 2024~2025년 자료로 학습했습니다.
- `weather_api.py`는 `python test_weather_api.py`(가짜 응답 사용)로 검증합니다.

## 산불 기록 API 연동
`fire_api.py`가 공공데이터포털 *산림청_산불발생통계(대국민포털)* API(같은 인증키, 별도 활용신청 필요)로 경기도 산불을 받아옵니다. 실행: `python fetch_fires_2026.py` → `data/산불_2026_api.csv`(2026-01-05~09-20, 93건). 기상도 `python fetch_2026.py`로 `data/기상_2026_api.csv`(2026-01-01~)를 받습니다. 원본 CSV는 수정하지 않으며, `core.py`가 있으면 자동으로 이어 붙입니다.
- 2026년 기록은 이력 조회와 '최근 90일 산불 건수'에만 쓰고 **학습·평가에는 쓰지 않아** 모델 성능은 그대로입니다.
- 원인 표기 변환(`쓰레기소각`→`쓰레기 태우기` 등), 구 단위 지역명 통합(`수원장안`→`수원`)을 했고 '원인 미상'은 API에 없어 '기타'에 포함됩니다.
- **대조 결과와 보정**: 2025년은 기존 CSV와 101건 일치, 2024년은 API에만 있는 10건이 있어 `data/산불_기상_병합.csv`에 직접 추가했습니다(2024~2025년 177 → 187건, 발생 지역일 171 → 181). 기존 177건은 전부 API에도 있었고 삭제·수정된 행은 없습니다. 추가 행의 관측소·기상 값은 같은 규칙으로 채웠습니다. 보정 후 모델을 다시 학습했습니다(아래 성능표는 보정 후 값).

- 병합 CSV의 기상은 *산불 당일* 값이라 이력 분석에만 쓰고, 예측 입력에는 쓰지 않습니다.

## 전처리
| 항목 | 처리 | 근거 |
|---|---|---|
| 중복 | (지점명, 일시) / 산불 완전 중복 확인 → 0건 | |
| 일강수량 빈칸 2,270행(62%) | 0mm로 처리 | 기상청 일자료의 빈칸은 대개 '강수 없음'. 빈칸인 날은 습도 67.6% vs 값이 있는 날 82.0%로 맑은 날 특징과 일치. 관측 누락이 일부 섞였을 수 있음 |
| 기온 7, 습도 15개 결측 | 같은 관측소의 *전날* 값으로 채움 | 연속 결측이 최대 4일. 뒤쪽 값은 미래 정보라 사용 안 함 |
| 지역명 | `용인처인` → `용인` | 같은 시, 같은 관측소 |
| 지역 단위 | 자료에 기록이 있는 26개 시군 | 기록이 한 건도 없는 시군(안양·부천·광명·구리·의왕)은 미발생인지 미수집인지 알 수 없어 제외 |

### 지역 ↔ 관측소 연결 근거
산불 위치는 시군 단위인데 관측소는 5곳뿐이라, **각 시군을 직선거리가 가장 가까운 관측소 1곳**에 연결했습니다 (`core.assign_stations`). 시군·관측소 좌표는 `data/merge.py`의 대략 값이며, 병합 CSV의 `기상관측지점`과 모두 일치함을 테스트로 확인했습니다. 날짜만으로 합치거나 한 관측소를 전체에 적용하지 않았습니다. 한계: 수원 관측소에 10개 시군이 연결되고, 가평·평택·안성은 30km 이상 떨어져 있습니다.

### 발생/미발생 구성
수집 범위를 기상 자료 전체 기간(2024-01-01~2025-12-31)으로 보고, 26개 지역 x 731일 = **19,006행**을 만든 뒤 산불 기록이 없는 날을 0으로 두었습니다. 발생 171행(0.9%) — 같은 지역·같은 날 2건이 6번 있어 177건이 171행이 됩니다. (한계: 산불 기록의 첫 날이 1/24라 1월 초 수집 여부는 확인 불가)

### 입력 시점 (미래 정보 차단)
**D일의 위험은 D-1일 밤까지의 정보로 예측**합니다. 입력 특성 14개:
- 기존 8개: 월(sin/cos), 전일 기온·습도·풍속, 최근 7일 강수합, 강수 1mm 미만 연속일수, 최근 90일 지역 산불 건수
- 달력 6개(예측 대상일 날짜만으로 계산, 미래 날짜 가능): 주말, 공휴일(`holidays` 패키지의 한국 달력, 대체·임시공휴일 포함), 평일 요일 더미(화·수·목·금, 월요일 기준). 계절은 기존 `월_sin/cos`가 담당하므로 월 변수는 추가하지 않았고, 토·일은 `주말`이 대신해 정보가 겹치지 않습니다.
- 달력 변수는 사람 활동의 **간접 지표**일 뿐 실제 입산·소각 활동을 측정한 값이 아닙니다.
- 산불 원인은 발생 *후* 기록되므로 이력 분석에만 쓰고 예측 입력에는 넣지 않습니다(테스트로 확인). 모두 `shift(1)` 이후 계산하며, "D일 값을 바꿔도 D일 특성이 변하지 않는다"를 테스트합니다.

## 모델과 배치 규칙 (구분)
- **예측 모델**: 표준화 + 로지스틱 회귀(`core.train_model`). 2024년으로 학습 → 2025년으로 평가(시간 순서 분할). 서비스용 최종 모델은 전체 기간으로 재학습.
- **배치 규칙**: 모델이 아님(`core.allocate_resources`). 위험 확률 상위 N개 지역에 `가용 수량 x 지역 확률 / 우선지역 확률 합`을 최대잔여법으로 정수 배분. 합계는 입력 수량 이하(테스트 300회 무작위 확인).
- 이번 버전에서 **예시 위험도는 쓰지 않았고** 모든 위험도는 실제 모델 예측값입니다. 차량·인력 수량은 실제 자료가 없어 **사용자 입력(가상) 값**이며, 지도 좌표도 대략 값입니다.

## 모델 성능 (2025년 평가, 발생 98일 / 9,490행)
세 모델을 같은 분할(2024 학습 → 2025 평가)·같은 표본·같은 경보 기준 선정 방법(학습기간 예측 확률 상위 10%)으로 비교했습니다. 변수 선택·경보 기준을 평가 데이터로 조정하지 않았습니다.

| 지표 | ① 계절만 | ② 기존(기상+이력) | ③ 기존+달력 (서비스 사용) |
|---|---|---|---|
| ROC-AUC | 0.766 | 0.846 | 0.843 |
| PR-AUC | 0.032 | 0.053 | 0.051 |
| 재현율 | 0.510 | 0.582 | 0.541 |
| 정밀도 | 0.031 | 0.047 | 0.044 |
| 경보 비율 | 0.167 | 0.128 | 0.126 |
| 경보 임계값(확률) | 1.75% | 2.08% | 2.10% |

**달력 변수는 성능을 개선하지 못했습니다.** ROC-AUC는 0.846(②) → 0.843(③)으로 사실상 같고(차이 95% 구간 -0.014~+0.008, 0 포함), 재현율은 오히려 0.582 → 0.541로 낮아졌습니다(발생 98일 중 약 4일 차이).

**2024년 라벨 보정의 영향**: 학습 라벨의 발생 지역일이 73 → 83일로 늘었고 평가(2025)는 그대로입니다. 보정 전(②/③: ROC-AUC 0.844/0.842, 재현율 0.571/0.582, 정밀도 0.050/0.050)과 비교하면 변화는 작고 방향도 일정하지 않아, 보정이 성능을 뚜렷하게 바꿨다고는 말할 수 없습니다. 평가 표본이 작아 이 정도 차이는 우연일 수 있습니다.

달력 효과 자체는 데이터로 따로 확인했습니다(데이터·모델 점검 화면 4번). 지역·날짜 단위 발생률은 평일 0.87%, 주말 1.19%, 공휴일 0.73%이고, 같은 달 평일 기준으로 보정한 비율은 주말 1.36배(63건 vs 기대 46.3건), 공휴일 1.09배(7건 vs 6.4건)입니다. 주말 쪽은 평일보다 높아 보이지만 통계 검정은 하지 않았고, 공휴일은 표본이 너무 작습니다.

전부 '미발생'이라 해도 정확도가 99.0%이므로 정확도는 의미가 없습니다. **위험 지역의 상대적 우선순위를 정하는 참고용**으로만 쓰세요.

## 한계
- 2년·발생 181일뿐이라 모델이 불안정하고 평가도 1년(2025)뿐입니다.
- 담뱃불·소각 등 사람 원인이 많아 기상만으로 설명되지 않습니다. 원인 미상·기타가 70건(39.5%)이라 원인 분석에도 한계가 있습니다. 임야 면적·지형 등은 미반영.
- 요일·주말·공휴일은 사람 활동의 간접 지표이며, 이번 평가에서 예측 성능 개선은 확인되지 않았습니다.
- 예측에 쓰는 기상은 *전날 관측*이며 예보가 아닙니다. 예보 연동은 향후 과제.
- 실제 진화 자원의 위치·수량 자료 미확보 → 사용자 입력으로 대체.
